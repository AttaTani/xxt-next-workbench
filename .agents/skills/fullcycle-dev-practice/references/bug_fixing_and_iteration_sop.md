# Bug 修复与切片式迭代治理规范 (Bug Fixing & Slicing SOP)

在复杂单体应用或高交互客户端系统的开发中，**“头痛医头、脚痛医脚”式的打补丁是系统崩塌和代码腐化的主要根源**。必须推行“根因治本、切片治理、测试护航、全量同步”的严密修复闭环。

---

## 一、切片式开发法 (Slice-Driven Iteration)

面对大体量重构、UI 减负或跨模块功能改造，**严禁一揽子合并式修改**。必须遵循纵向切片（Vertical Slice）原则。

### 1.1 什么是高质量切片？
- **自闭环 (Self-Contained)**：每个切片只解决一个核心关注点（如纯 DOM 结构，或纯手势调度）；
- **可独立验证 (Independently Verifiable)**：每个切片必须具备专属的自动化测试脚本，执行后立即可验证；
- **零破坏性 (Non-Breaking)**：切片实施后，已有旧功能保持 100% 可用，不引入中间状态的半死代码。

### 1.2 标准重构切片范式（以前端重构为例）
```
┌─────────────────────────────────────────────────────────────┐
│ Slice 1: 骨架与视口高度治理 (Skeleton & Viewport)            │
│ - 目标: 根除小屏 (667px) 弹性坍塌与滚动穿透                   │
│ - 验证: test_warehouse_and_theme_refactor.js                │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ Slice 2: 交互抽屉与动态挂载 (Drawers & Modals)               │
│ - 目标: 抽屉 DOM 简化、手势拖拽绑定、三层视差遮罩             │
│ - 验证: test_all_drawers.js                                 │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ Slice 3: 主题系统与样式解耦 (Tokens & Theming)               │
│ - 目标: 全局 CSS Token 分层、三级预设主题平滑切换             │
│ - 验证: test_theme_features.js                              │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ Slice 4: 健壮性加固与降级兜底 (Hardening & Edge Cases)       │
│ - 目标: 脏数据过滤白名单、手势裁决防冲突、无痕清理           │
│ - 验证: test_slice4_hardening.js                            │
└─────────────────────────────────────────────────────────────┘
```

## 二、根因剖析法则 (Root-Cause-First Principle)

**严禁**使用表面掩盖式的“临时补丁”修复 Bug（如滥用 `!important` 覆盖样式、使用 `setTimeout(..., 500)` 掩盖时序竞争、用全局 `try-catch` 吞没真正异常）。

### 2.1 经典根因分析模型
必须直击技术机理的底层本质，例如：

| 表面缺陷现象 | 浅层伪修复（严厉禁止） | 深度根因机理剖析 (Root Cause) | 彻底根治方案 |
| :--- | :--- | :--- | :--- |
| **卡片内容在小屏被截断** | 强制加 `overflow: auto`，出现双层丑陋滚动条 | Flex 布局中未设置 `min-height: 0`，导致默认 `min-height: auto` 拒绝收缩，撑破父容器 | 设置 `flex: 1 1 0; min-height: 0; display: flex; flex-direction: column;` 形成受控弹性盒 |
| **手机端滑动列表时无法滚动** | 移除手势事件监听 | 容器上未显式指定 `touch-action`，浏览器默认手势引擎与 JS 手势拦截器发生调度冲突 | 显式声明 `touch-action: pan-y;`，赋予浏览器垂直原生滚动裁决权，横向滑动手势由代码捕获 |
| **抽屉展开后穿透滚动背景** | 动态给 `body` 增加 `overflow: hidden`，导致页面跳顶失焦 | 移动端 iOS Safari 忽略 `body` 溢出限制，触摸事件在冒泡阶段穿透到底层主视口 | 在遮罩层拦截 `touchmove` 事件并调用 `e.preventDefault()`，同时内部容器开启 `-webkit-overflow-scrolling: touch` |

## 三、Playwright 自动化测试护航 (Test-First & Negative Testing)

没有自动化测试保证的重构，等同于无保护的高空钢丝漫步。

### 3.1 编写无头自动化脚本的五大维度
针对核心用户体验，使用 Playwright 构建独立的测试文件（存放在 `05_测试与验收_QA/`）：
1. **尺寸极限压测**：设置 iPhone SE (`375x667`) 与标准手机视口，测量关键元素的 `getBoundingClientRect()`，断言高度无溢出、无意外滚动条；
2. **状态机全覆盖**：对状态转换（如抽屉 打开 $\rightarrow$ 切换Tab $\rightarrow$ 遮罩点击 $\rightarrow$ 关闭）做全路径状态机验证；
3. **真实手势模拟**：利用 `page.mouse` 或 touch 事件序列（`touchstart` $\rightarrow$ `touchmove` $\rightarrow$ `touchend`），模拟真实手指划动位移；
4. **数据持久化边界**：校验 `localStorage` 写入、版本迁移、脏数据结构解析容错（防白屏崩溃）；
5. **逆向异常测试 (Negative Testing)**：故意输入恶意格式数据、注入非法字段，断言系统能优雅拦截并降级提示。

## 四、四重闭环同步法则 (Documentation Sync Rule)

代码修改不是修复的终点。每一次 Bug 攻坚完成并通过全量测试后，必须立即触发四重同步：

```
[源码变更完成] ──> [1. QA报告沉淀] ──> [2. PRD体验指标更新] ──> [3. 维护手册基线同步] ──> [4. Git语义化提交]
```

1. **沉淀 QA 分析报告**：在 `05_测试与验收_QA/` 生成或更新分析报告，记录根因与测试断言；
2. **回写 PRD 需求文档**：在 `02_产品需求_PRD/` 补齐边界规则（如明确“在小于 700px 屏幕下隐藏装饰性元素”）；
3. **同步系统维护手册**：在 `03_技术方案_Architecture/` 更新最新 DOM 结构、CSS 变量表与关键函数签名；
4. **生成语义化 Git Commit**：提交清晰规范的 Commit 记录。
