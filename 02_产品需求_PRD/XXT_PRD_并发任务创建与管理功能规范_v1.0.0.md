## 1. 业务背景与需求动机 (Business Context & Motivation)

### 1.1 现存系统局限性
当前挂机引擎为**单任务单流水线设计**：
- 前端只提供单一输入框，全局仅维护单个课程的 URL 与 Playwright 页面；
- 当用户拥有多门课程（例如同时修读《史记导读》、《马克思主义基本原理》、《大学英语》等 3~5 门课）时，必须等待前一门课程全量挂机完成并由人工再次进入网页复制黏贴下一门课程的 URL；
- 无法直观监控多门课程的进度流向，无法进行批量作业编排，工作效率受限。

### 1.2 核心业务诉求
用户需要在 Web 控制台具备**“并发任务创建、队列调度、优先级控制、多任务状态监控”**的全生命周期管理能力：
1. **多任务录入**：支持单课程快速创建与多课程批量粘贴导入；
2. **并发节流控制**：支持动态调整同时运行的 Worker 数量（例如 1~3 路并发），在防封风控与刷课效率间取得平衡；
3. **队列流转看板**：直观展示排队中、运行中、已完成、异常任务，支持任意启停与置顶；
4. **多画面监视视口**：支持在前端切换查看不同并发课程的实时播放画面。

## 2. 平台风控特征与技术可行性分析 (Risk & Feasibility Analysis)

### 2.1 超星服务端风控模型考量
| 风险维度 | 超星防作弊规则描述 | 引擎工程应对方案 |
| :--- | :--- | :--- |
| **同账号跨课程并发** | 同一账号在不同设备/不同 IP 同时高频观看不同视频，可能触发多地登录或异常高并发告警。 | **严格节流机制**：默认并发数限制为 `1`（队列自动轮转），最大可选并发为 `2~3`（同原生宽带 IP 下拟真多标签），严禁无节制高并发。 |
| **同课程内任务点并发** | 同一门课同时打开多个小节播放，超星服务器日志会记录“时间重叠冲突”，直接判定作弊并清空学时。 | **同一课程强互斥**：系统禁止对同一门课程创建多个活跃播放 Worker，同课程内必须串行推进。 |
| **客户端硬件开销** | 每个无头 Chromium 标签页解码 1080P/720P 视频并渲染 Canvas。 | 启用 `--disable-accelerated-2d-canvas`，单任务内存消耗控制在 **120MB ~ 180MB**，3 并发总内存占用 $\le 600\text{MB}$，家宽 PC 完全零压力。 |

### 2.2 浏览器上下文隔离选型
- **选型方案**：**单持久化 BrowserContext + 多 Page 隔离模式**。
  - **优势**：同一个已登录账号的所有页面共享已认证 Cookie（37 个 Session Cookies），无需针对每门课重复登录；
  - 每个课程独立绑定一个 Playwright `Page` 实例与独立的监控循环，小节切换与答题彼此完全解耦、互不阻塞。

### 3.1 模块 F1：任务创建器 (Task Creator)
1. **单任务添加**：
   - 输入框：课程播放页或大纲页 URL（支持输入包含 `courseId`、`clazzid`、`enc` 的超星标准链接）；
   - 自定义属性：
     - 任务别名（可选，若留空则自动进入页面后抓取 `h1/h2` 课程名）；
     - 专属倍速（`1.0x` / `1.25x` / `1.5x`，默认遵循全局安全模式）；
     - 自动答题开关（默认开启，调用已集成的 Qwen-VL）；
   - 动作：点击【添加至队列】立即入库。
2. **批量文本导入**：
   - 多行文本域，支持用户一次性粘贴 5~10 个课程链接（每行一个）；
   - 客户端进行正则校验与去重，一键批量生成排队任务。

### 3.2 模块 F2：全局并发调度控制器 (Concurrency Controller)
1. **最大并发数设定（Max Concurrency）**：
   - 下拉选择或滑块控制：`1`、`2`、`3`、`4`（默认 `1`，标记“官方防风控推荐”；选择 $\ge 3$ 时呈现黄色温和提示）；
   - 动态生效：修改后即刻生效，调度器自动根据活跃 Worker 数决定是否从队列唤醒下一个任务。
2. **全局批处理动作**：
   - 【一键全部启动】：激活所有处于“排队中”与“已暂停”的任务，按优先级依次填满并发槽位；
   - 【一键全部暂停】：平稳暂停所有运行中页面；
   - 【清理已完成】：一键从列表移除状态为 `COMPLETED` 的历史任务。

### 3.3 模块 F3：任务看板与状态列表 (Task Kanban & List)
1. **状态机流转**：
   - `QUEUED`（排队中）：已录入，等待并发槽位空闲；
   - `RUNNING`（挂机中）：已分配独立 Page 正在实时播放；
   - `PAUSED`（已暂停）：用户主动挂起；
   - `COMPLETED`（已完成）：整门课程全部小节与任务点已刷完；
   - `ERROR`（异常阻断）：触发风控滑块验证码或网络断连。
2. **任务卡片要素**：
   - 任务编号、课程名称、当前小节标题、数字进度条（如 `78% (841s/1072s)`）；
   - 操作按钮组：[启动/暂停]、[置顶优先（移动至队首）]、[下一小节]、[删除任务]；
   - 点击卡片可在右侧实时联动切换监视画面。

### 3.4 模块 F4：多画面实时监视视口 (Multi-Viewport Monitor)
1. **Tab 联动切换**：
   - 顶栏显示当前所有运行中任务的快捷选项卡（Tab 1、Tab 2）；
   - 切换选项卡无感刷新该任务关联的专属页面快照（`screen_{taskId}.png`）；
2. **状态指示灯**：
   - 视口右上角显示当前画面更新时间戳及是否处于“随堂测验”状态。

### 3.5 模块 F5：结构化分任务日志面板 (Structured Task Log Stream)
1. **多路日志流聚合**：
   - 日志条目增加 `[任务名/ID]` 标签，区分不同并发任务输出；
2. **日志筛选器**：
   - 下拉菜单支持切换 `[全部任务]` 或 `[仅看当前选中任务]`，避免多任务交替刷屏造成视觉困扰。

## 4. 后端架构与调度引擎演进 (Backend Architecture Evolution)

### 4.1 架构分层重构
从当前的单例 `XuexitongEngine` 拆分演进为三层架构：

```
                    ┌───────────────────────────┐
                    │  Express Web Server (3888) │
                    └─────────────┬─────────────┘
                                  │ REST API
                    ┌─────────────▼─────────────┐
                    │    TaskManager (调度中心)  │
                    │ - Concurrency Semaphore   │
                    │ - Task Queue & Priority   │
                    │ - Persistence (tasks.json)│
                    └─────────────┬─────────────┘
                                  │ 分发 Worker
          ┌───────────────────────┼───────────────────────┐
          ▼                       ▼                       ▼
   [TaskWorker #1]         [TaskWorker #2]         [TaskWorker #3]
    - Page 1                - Page 2                - Page 3
    - Video Loop 1          - Video Loop 2          - Video Loop 3
    - Qwen-VL Handler       - Qwen-VL Handler       - Qwen-VL Handler
```

### 4.2 调度算法逻辑 (Scheduling Algorithm)
1. **信号量机制（Concurrency Semaphore）**：
   设当前运行中任务集合为 $R$，用户设定的最大并发数为 $C$。
   - 当 $|R| < C$ 且就绪队列 $Q$ 非空时：从 $Q$ 队首取出优先级最高的任务 $T$，为其创建 Playwright `Page`，状态转为 `RUNNING`；
   - 当任务 $T$ 触发整门课完成（`COMPLETED`）或发生致命错误时：释放对应的 `Page` 资源，$|R| \leftarrow |R| - 1$，触发下一轮调度唤醒。
2. **数据持久化（State Hydration）**：
   - 任务清单实时落盘至 `vps-service/userData/tasks.json`；
   - 服务重启时自动加载所有未完成任务，重新进入调度队列，保证进度不丢失。

## 5. 数据契约与接口规范 (Data Contracts & API Design)

### 5.1 核心数据模型 (Task Schema)
```typescript
interface XuexitongTask {
    id: string;               // 唯一哈希 ID (例如: "task_1728876123")
    name: string;             // 课程显示名称 (例如: "史记·太史公自传")
    url: string;              // 课程 URL
    status: 'QUEUED' | 'RUNNING' | 'PAUSED' | 'COMPLETED' | 'ERROR';
    playbackRate: number;     // 播放倍速 (1.0, 1.25, 1.5)
    progress: {
        unitTitle: string;    // 当前小节 (例如: "3.4 江南义军的壮大")
        percentage: number;   // 进度百分比 (0-100)
        currentTime: number;  // 播放当前秒
        duration: number;     // 总时长秒
    };
    errorMessage?: string;    // 异常描述
    createdAt: number;
    updatedAt: number;
}
```

### 5.2 RESTful API 契约设计

| 方法 | 路径 | 描述 | 请求 Payload / 查询参数 |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/tasks` | 获取所有任务列表及并发配置 | 无 |
| `POST` | `/api/tasks` | 新建单个课程挂机任务 | `{ url, name?, playbackRate? }` |
| `POST` | `/api/tasks/batch` | 批量创建课程任务 | `{ urls: string[], playbackRate? }` |
| `POST` | `/api/tasks/:id/start` | 启动/恢复指定任务 | 无 |
| `POST` | `/api/tasks/:id/pause` | 暂停指定任务 | 无 |
| `DELETE` | `/api/tasks/:id` | 删除指定任务并释放页面 | 无 |
| `POST` | `/api/tasks/:id/priority` | 调整任务优先级（置顶） | `{ action: 'top' \| 'up' \| 'down' }` |
| `POST` | `/api/settings/concurrency`| 调整全局并发 Worker 数 | `{ maxConcurrent: number }` |
| `GET` | `/api/tasks/:id/screenshot` | 获取指定任务的实时截屏 | 二进制图片流 |

## 6. 切片化实施路线与里程碑 (Sliced Implementation Roadmap)

为保障生产环境不中断现行挂机，实施分为 4 个可独立验证的切片：

### 切片 C1：后端调度中心与 Worker 抽象 (Backend Engine Architecture)

- **验证标准**：通过本地测试脚本，验证同时注入 3 个任务时，调度器严格按照并发上限（如并发设为 1 时依次执行，并发设为 2 时并行拉起 2 个 Page）。

- **范围**：在 `web.js` 中接入上述所有任务创建、批处理、并发控制与画面路由接口。
- **验证标准**：使用 HTTP 请求或 PowerShell 验证任务的新增、暂停、批量导入与状态同步无异常。

### 切片 C3：前端工作台 UI 重构 (Frontend UI & Kanban Layout)

## 7. 验收标准与交付物清单 (Acceptance Criteria)

1. [ ] **防作弊风控保障**：系统全局并发数必须具备严格上限设置（默认 1，最大 3），同门课程不得并发创建；
2. [ ] **会话共享与免二次登录**：所有任务统一复用已存在的 37 个认证 Cookies，无需重复扫码；
3. [ ] **状态持久化与断点续挂**：意外重启或手动重启后，`tasks.json` 自动恢复排队与进度，不丢失已添加的课程列表；
4. [ ] **直观易用的前端看板**：支持一键批量粘贴多门课程，支持一键切换监视各任务画面；
5. [ ] **完全静默与零干扰**：多任务运行依然保持纯无头、无黑框、不抢夺用户日常键鼠焦点。
